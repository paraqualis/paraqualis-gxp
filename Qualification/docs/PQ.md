## 1. What Performance Qualification proves (plain English)

Performance Qualification asks one question: **does the system actually do its intended job, with realistic use and realistic data?** Where Installation Qualification checks the system is correctly *in place* and Operational Qualification checks each function *works to spec*, PQ exercises the **whole job end-to-end** and traces each result back to a stated requirement (`URS-NNN`). Each test-case below maps one URS requirement to the place its real-world behaviour can be evidenced.

The system under test is `paraqualis-gxp` — a Claude Code toolkit for life-sciences regulatory and computer-system-validation work (regulatory commands, auto-invoked advisory skills, parallel qualification sub-agents, an openFDA tool server, and a document-protection hook). Because the qualification engine uses an LLM to generate GxP-impacting evidence, the AI-specific test-cases (`PQ-AI-0NN`) additionally check that AI claims are traceable, human-reviewed, scoped to a stated Context of Use, and consistent.

## 2. Context of Use and self-qualification caveat (AI governance)

**Context of Use (COU):** the AI components (the qualification engine and its IQ/OQ/PQ sub-agents, plus the two advisory skills) are used to **draft** regulatory analysis and qualification evidence for review by qualified personnel. The output is decision-**support**, not an automated decision. **Self-qualification caveat:** this engine is itself a **GxP-impacting tool that would require its own qualification** before its output is relied upon as formal evidence; it structures and accelerates evidence, it **does not self-certify**. All AI output is issued **DRAFT requiring human review** by the named reviewer roles below before any reliance.

## 3. How to read the result columns

Each test-case ships with its script/procedure (in `Qualification/scripts/`) and a **blank execution-record block** that becomes the evidence once the test is run by a qualified person. Results are reported in three honest categories — **PASS**, **FAIL**, **not-yet-executed** — and **a skip is never counted as a pass**. The "As-built indication" column records what the *generation-time* dry-run of the script showed (where it could be run read-only in this environment); it is an indication only and **does not replace** the witnessed execution record.
