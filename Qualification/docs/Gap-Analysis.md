# Gap Analysis — paraqualis-skills v1.1.0

**DRAFT — pending review and approval by appropriately qualified and authorized personnel.**

This is the consolidated gap register for the qualification pack — both the auditable QA
deliverable **and** the file an engineer feeds to Claude in the repo to close the gaps. Each
gap is stage-prefixed (`GIQ`/`GOQ`/`GPQ`) so the three parallel stages never collide. Gaps
surfaced by more than one stage are **merged into a single entry**, named for the stage of
greatest impact, with every contributing test-case listed. A gap is **closed only when its
Definition-of-Done test-case passes.**

## Notes

- **Install-dependent gaps — remediation 2026-06-17:** a pinned `requirements.txt` was added
  (closing the manifest part of GIQ-001); `python-docx` and `openpyxl` were installed so the
  Word/Excel path is fully operable; and **pre-flight checks** were added to `build_docx.py`,
  `build_xlsx.py` and `server.py` so nothing runs against a missing dependency (or, for the
  server, an unsupported Python) — each fails loud with the exact install command. The one
  item that **cannot** be closed on this box is `mcp`: it requires Python ≥3.10 and the box
  runs 3.9.6, so the openFDA server needs a Python upgrade before it can run. The pre-flight
  check makes that condition explicit at run time rather than letting it fail obscurely.
- **Document control (decision 2026-06-17):** these qualification documents are controlled by
  **approval sign-off plus the per-document version-history section** (added at the end of
  each document); a separate running audit log is **not** maintained for the documents
  themselves. *(This concerns the documents only — the software-side audit-trail/logging gap
  GIQ-007 for the MCP server and hook is unrelated and remains open.)*
- **Automated test suite (decision 2026-06-17):** GOQ-004 (no automated unit-test suite) is **scoped out** as a risk-based, proportionate decision — for a system of this size and complexity (a small set of declarative assets plus short Python helpers), a full unit-test suite is not warranted under GAMP 5 proportionality. OQ-030 is recorded **N/A — risk-based**, not a failure; the inline behavioural checks in the OQ section still evidence the functions.
- **Severity is named by greatest impact.** Where a gap surfaced in several stages (e.g. the
  logging gap GIQ-007 appeared in IQ, OQ, and PQ), it is one entry listing every contributing
  test-case, not three.
- This file is transient and belongs to the target system — do **not** commit it to long-term
  memory. Feed it to a coding agent in the repo to work the gaps; each gap's Definition-of-Done
  is the test it must make pass.
